# Релизы и OTA-обновления

## Зачем

Правка JS (экраны, хуки, работа с сетью) доезжает до людей двумя путями:

| Путь | Что доставляет | Сколько идёт |
|---|---|---|
| Релиз в Google Play | всё, включая нативную часть | дни, с ревью |
| `eas update` (OTA) | только JS-бандл и ассеты | минуты |

Для приложения про безопасность на дороге ждать ревью ради исправления
логики — слишком долго. Поэтому подключён `expo-updates`.

## Разовая настройка

OTA выключены, пока не задан `EAS_PROJECT_ID`. Приложение при этом собирается
и работает как раньше — просто молча не ходит за обновлениями. Чтобы включить:

```bash
npx eas login
npx eas init          # создаст проект и покажет его ID
```

Полученный ID положить в `.env` в корне репозитория:

```
EAS_PROJECT_ID=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
```

`.env` под `.gitignore` — в репозиторий он не попадает. Для CI и сборок на EAS
ту же переменную нужно завести в настройках проекта (`eas secret:create`).

После этого **нужна одна сборка через Play**: `expo-updates` — нативный модуль,
и OTA начнут работать только с той версии, в которую он вошёл.

## Обычный цикл

**Правка только в JS/TS** — карта, экраны, хуки, работа с API:

```bash
npm run typecheck && npm run lint
npm run update:production
```

Обновление скачается в фоне при следующем запуске приложения и применится
на запуске после него. Посреди поездки перезагрузки не будет — это осознанно.

**Правка в нативной части** — новая библиотека с нативным кодом, изменения в
`app.config.js` (права, плагины, иконки):

```bash
npm run build:android
npm run submit:android
```

## Как понять, что нужен полноценный релиз

Не гадать. Политика `runtimeVersion` — `fingerprint`: EAS считает хеш нативной
части проекта и отдаёт обновление только сборкам с совпадающим хешем. Если
изменилось что-то нативное, хеш разойдётся и старые сборки просто не увидят
обновление — вместо того чтобы получить бандл, который они не смогут запустить.

Проверить хеш до публикации:

```bash
npx expo-updates fingerprint:generate
```

Альтернативная политика `appVersion` намеренно не используется: там достаточно
добавить нативный модуль и забыть поднять `version`, чтобы OTA уехало в
бинарник, где этого модуля нет, и приложение падало бы на старте у всех.

## Какая сборка у пользователя

Экран профиля показывает строку вида `1.0.0 · production · a1b2c3d4`, где
последнее — начало идентификатора обновления. Если его нет, человек сидит на
встроенном бандле из Play. При разборе жалоб спрашивать именно эту строку.

## Откат

```bash
npx eas update:list --branch production     # найти предыдущее обновление
npx eas update:republish --group <id>
```

Откат — тоже OTA, доезжает за минуты. Это главная причина, по которой стоит
держать OTA включёнными: неудачная правка откатывается, не дожидаясь ревью.
